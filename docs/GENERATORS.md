# Generators: capabilities and the pose-native option

The generate stage has one exit per generator. Each adapter in `providers/` declares what it can do; the UI offers
only that, and says in one sentence what it cannot do and what the nearest option is. This page records the
capability shape, the Wan research behind the third generator, and what each generator cannot do.
Companion pages: `docs/PROVIDERS.md` (the two Seedance adapters), `docs/COSTS-RESEARCH.md` (prices),
`docs/WORLD-LOOK-EXPORT-SPEC.md` §5 (the contract).

## Capability shape (`providers/capabilities.py`)

`normalize(caps)` gives every adapter the same keys; the legacy keys in `providers.base.CAPABILITY_KEYS`
(`draft_resolution`, `final_resolution`, `finalize`, `finalize_identical`, `needs_webhook`, `hosting`, …) stay as they are.

| key | meaning | fal · Seedance 2.5 | Enhancor | Wan 2.2 Animate · replace |
|---|---|---|---|---|
| `resolutions` | what the endpoint renders | `480p, 720p, 1080p` | `1080p` | `480p, 580p, 720p` |
| `draft` | a cheap draft exists | true (480p, `draft: true`) | true (`is_draft`) | false: the first render is the final |
| `finalize` | how the draft completes | `complete_draft` | `complete_draft` | `null` |
| `max_seconds` | longest prepared clip | 30 | 30 | 30 (our cap; fal publishes none) |
| `audio` | generates audio | true | true | false (the original audio is restored anyway) |
| `tasks` | Seedance task names | `auto, reference, editing, extension` | `[]` (no task setting) | `[]` (pose-locked) |
| `ref_images_max` | reference images per request | 30 (fal OpenAPI, total files ≤ 50) | 30 (same model; Enhancor publishes no cap) | 1 |
| `slots` | `set_ref`, `look_ref`, `char2`, `identity_video` | all true | all true | all false |
| `control` | how the prepared clip steers the result | `video` (edit / reference) | `video` | `pose` |
| `fps` | output frame rate | 24 | 24 | 16 (fal's billing unit; output fps confirmed on the first paid run) |
| `prompt` | a prompt is sent | true | true | false |

`supports(caps, slots, others)` returns `[{slot, message, fix}]` for a slots object (`set.mode`, `look.mode`,
`generator.task` / `generator.resolution`, plus `char2`, `char1_video`, `seconds` facts about the run). Examples for Wan:

- set: "Wan 2.2 Animate · replace (fal) takes one reference image: the set image is ignored here." → "Use Enhancor for a set reference, or describe the set in the prompt." (the nearest option is the first of `others` that supports the slot; "Seedance via fal" when none is given)
- task: "… has no "reference" task; it always keeps the pose and timing of the prepared clip and sends no prompt." → "Use fal · Seedance 2.5 for the reference task."
- Enhancor with a derived task: "Enhancor has no task switch; the request is sent the same way whatever the set mode is." → "Nothing to change: the set mode only affects the prompt text here."

`summary(caps)` is the one-line description for the generator picker, e.g. for Wan:
`480p/580p/720p · one render, no draft/complete · no audio (original audio restored) · pose-locked · 1 reference image`.

`providers.GENERATORS` = `('enhancor', 'fal', 'wan')` lists every adapter; `providers.PROVIDERS` stays the Seedance
pair so `default_provider()`, `GET /providers` and the regression suite are unchanged. `providers.normalized_capabilities(name)`
returns the normalized shape for one adapter.

### Why `fal-ai/wan/v2.2-14b/animate/replace`

- It is the only endpoint whose *purpose* is our task: replace the person in an existing clip while keeping that
  clip's pose, expression, timing, background and lighting. Everything else either needs a prompt to carry the
  intent (VACE, 2.7 edit-video), drops our scene (animate/move, wan-motion) or has no image input (a14b v2v).
- Pose-native (`control: 'pose'`): the driving video is read for skeleton and face, so the dialogue timing and the
  mouth motion of the prepared clip are followed frame by frame instead of "interpreted" the way Seedance's
  reference task does.
- Price: $0.60 for a 10 s clip at 480p, $1.20 at 720p, against $2.65 for a Seedance 480p draft and $13.97 for its
  1080p completion. A cheap second opinion on the same prepared clip.
- Same account and the same upload path as the fal Seedance adapter (`FAL_KEY`, `fal_client.upload_file`).

### What it cannot do (and what the UI says)

- **One reference image only**, no prompt: the set, look and light slots and Character 2 do not reach the model.
  → "Wan takes one reference image: the set image is ignored here. Use Seedance via fal for a set reference."
- **No identity video** for Character 1. → "Pick one clear frame of the identity video as the Character 1 image."
- **No draft/complete**: one render, max 720p. `finalize()` raises "Wan Animate has no draft to complete: the first
  render is the final. Re-run the generate stage at 720p for a sharper clip, or use Seedance via fal for a 480p
  draft that completes at 1080p." (`finalize: null`, `finalize_identical: false`).
- **No task switch**: the Set slot's derived task is shown as not applicable; the prompt builder's text is kept in
  `generation.json` for the record but not sent.
- **No audio** is generated; the orchestrator restores the original audio over the result as for every generator.
- **Background comes from the prepared clip**: with the default composite (depth person over the real frames or
  the mesh over the original) the room is kept; with Background `full_depth` or `plain` the output keeps that
  depth or flat background. Depth-coloured bodies may confuse the pose reader; face-mesh mode (real pixels with
  thin lines) is the safer input. Confirm on the first paid run.
- Length: fal publishes no limit; the adapter keeps the Seedance input rules (1.8–30.2 s, ≤ 200 MB, 300–6000 px,
  24–60 fps) so a clip that works for Seedance works here.

## Wan adapter (`providers/wan.py`)

- `Wan(resolution=None)`, `name='wan'`, `label='Wan 2.2 Animate · replace (fal)'`, `draft_endpoint=APP`, `final_endpoint=None`.
- `submit_draft(prepared, refs, prompt, *, folder, status, task=None, resolution=None)`: refuses a video Character 1
  or a Character 2 with a plain sentence and the nearest option **before** any upload; checks the local constraints;
  `record_call(folder, 'fal', APP)` (offline mode refuses here); uploads the video then the image with
  `fal_client.upload_file`; payload `{'video_url', 'image_url', 'resolution'}` written to `wan-request.json` and
  `seedance-request.json` (the orchestrator and the UI read the latter); `fal_client.submit(APP, arguments=payload)`.
  `prompt` and `task` are accepted for the shared orchestrator call and ignored (the endpoint takes neither).
- Resolution: explicit argument > `<run>/wan-options.json` `{"resolution": "720p"}` (what the Phase B tool writes)
  > `WAN_RESOLUTION` in `.env` > `480p`. Anything else → "Wan Animate renders at 480p, 580p, 720p; …".
- `poll()` maps `Queued` / `InProgress` / `Completed` like the fal adapter, saves `wan-result.json`, returns
  `result_url`, `seed`, `auto_prompt` (the model's own prompt) and `draft_id: None`.
- Errors from `fal_client` are re-raised as `RuntimeError` with `FAL_KEY` redacted and no chained traceback.
- Prices in `stages/costs.py`: `wan` (480p, $0.06 per clip second at 24 fps), `wan_580p` ($0.09), `wan_720p` ($0.12);
  `estimate_tool('wan' | 'wan_fal', seconds, {'resolution'})` picks the right one. No `wan_complete`.

## Generator slot in the app (Phase B)

- **Registry.** `providers.GENERATORS = ('enhancor', 'fal', 'wan')` is what `seedance_bridge.submit` / `provider_for`, `POST /jobs/{id}/seedance`
  (`provider` field) and `GET /providers` accept and list; `providers.PROVIDERS` stays the Seedance pair and `default_provider()`
  still returns only `enhancor` or `fal`.
- **`GET /providers`** → `{default, generators: [...], providers: {name: normalized capabilities + configured + summary}}`. No key names
  or values appear here (the regression suite checks `FAL_KEY` is absent).
- **`GET /jobs/{id}/generators`** (`?char1_video=1&char2=1` for references picked in the form but not saved yet) → per generator:
  normalized capabilities, `configured`, `key` (the `.env` variable to add when not configured), `summary`, `estimate_usd` at this
  run's length (wan at the resolution saved in the slots; plus `estimates` per resolution), and `limits` =
  `supports(caps, slots + facts)`: `[{slot, message, fix}]` with the nearest **configured** generator named in `fix`. Also `chosen`
  (`slots.generator.name`), `resolution`, `task` (the effective Seedance task) and `seconds`.
- **`stages/generate.py`** tool `wan_fal` (paid; params `char1`, `resolution` 480p | 580p | 720p; no `task`, no `char2`): writes
  `wan-options.json`, calls `seedance_bridge.submit(provider='wan')`. `write_wan_options(folder, resolution=None)` picks the explicit
  value, else `slots.generator.resolution`, else 480p. The generate report's `tool` is `wan_fal` (`TOOL_FOR_PROVIDER`); `generation.json`
  has `provider: wan`, `task: "not applicable"` and a `task_note`.
- **`POST /jobs/{id}/seedance`** with `provider=wan`: the estimate on the cost gate is the wan price at the slots' resolution;
  `wan-options.json` is written before the adapter runs. **`POST /jobs/{id}/hd`** on a wan run answers 400
  `{message: "Wan Animate has no draft to complete: …", fix: …}` before any cost gate; `GET /jobs/{id}/run` carries
  `estimates.draft.wan` and `estimates.complete.wan: null`.
- **`static/generator.js`** (`mountGenerator(host, {select, facts, onChange})`, mounted by `draft.js` into `[data-slot=generator]`):
  one radio button per generator (configured ones enabled with the estimate; unconfigured ones disabled with "not configured ·
  FAL_KEY" and the `.env` line in the tooltip), the `summary` line, the `limits` list ("Set · Wan … takes one reference image: the
  set image is ignored here. Use fal · Seedance 2.5 for a set reference …"), a Resolution select only when the generator renders
  once at a chosen resolution (wan; Seedance drafts are fixed), and the draft / final line (draft → final on approval, or "One
  render at 480p. Wan Animate has no draft to complete …"). Choices are saved with `PUT /jobs/{id}/slots {generator: {name,
  resolution}}`; the panel reloads whenever the slots panel reports a save (so changing the Set mode refreshes the limits).
  It keeps the legacy `select[name=provider]` on the same value (and hides its row), so the form submits the same provider.
- **Disabled options.** The Set select's `set_ref` and the Look select's `style_ref` options are disabled (with the sentence as the
  tooltip and "· not with Wan …" in the label) when the chosen generator has no such slot; the Character 2 upload is disabled with
  the sentence; the Character 1 input only accepts images when the generator takes no identity video. The task line in the slots
  panel reads `tasks: []` from the capabilities ("… has no task setting (it always keeps the pose and timing of the prepared clip),
  so this is recorded as not applicable there") instead of a hard-coded provider name.
- **Step 04.** For a run whose generator has `finalize: null` the HD button is hidden and the hint shows `finalize_hint`
  ("This render is the final").
- **Degraded mode.** With no keys every generator is listed unconfigured with its key name; nothing else in prep, edit or export
  depends on it (`GET /jobs/{id}/run`, `/slots`, `/export`, `/edits` keep answering).
